# 部署币种与时区

每套部署、数据库固定使用一种币种。界面语言、资源区域、计价币种、账期时区相互独立；不做汇率换算，不改表，也不转换历史数据。

## 配置

- `STUDIO_LOGIN_CURRENCY`：`CNY` 或 `USD`，默认 `CNY`。
- `TZ`：应用部署环境的时区，例如 `Asia/Shanghai`、`UTC`、`America/Los_Angeles`。未设置或为空时固定使用 `Asia/Shanghai`，不随机器所在时区改变；显式设置时使用指定时区，无效值启动失败。

已纳入的 LAS 计费项按部署币种选择内置价目表：`OriginalPrice` 对应客户单价，`DiscountPrice` 对应内部成本单价；`operator_unit` 的价格同时用于 Core 通过它查价的 OU 计费项。CNY 部署使用人民币 LAS 价目表，以及方舟 Seedream 和 Seed 语言模型刊例价。USD 部署使用提供的 54 项 USD LAS 阶段价格，以及 [BytePlus ModelArk 价格表](https://docs.byteplus.com/en/docs/modelark/model-pricing)中的 Seedream 和四个 Seed 语言模型标准在线价，不做汇率换算。BytePlus 未列出 Seed 2.1 Pro 的 USD 价格；该项和其他缺少 USD 报价的计费项保留客户价 `0`、内部成本价 `0`，使用前须按实际报价配置。Seedream 5.0 Pro 的固定单图价格只覆盖默认低分辨率场景，高分辨率、图层拆分及额外输入图需另行计价。未知计费项继续使用客户单价 `1`、成本单价 `0.5`。管理员可在页面配置具体计费项的价格；页面单价允许为零，精度保持原有规则。

Docker 镜像保留 `TZ=Asia/Shanghai` 默认值，以兼容既有部署。海外部署通过容器环境变量覆盖 `TZ`，不要假设容器自动继承宿主机时区。USD 不自动对应某个美国时区，英文/日文界面也不改变部署币种。

## 金额链路

CNY 部署的五个 Seed 语言模型、USD 部署中 BytePlus 已报价的四个 Seed 语言模型，在没有显式价格时使用各自币种的可编辑 Token 档位规则。启动时，已启用、客户价与成本价均为零且没有公式的旧平台级 Seed 价格记录会按部署币种升级；旧的 `ark_seed_...` 公式也会转换为结构化规则。USD 的 Seed 2.1 Pro 因无公开报价不自动升级。其他管理员配置的平台价格和配置组价格不会被启动流程覆盖。

`GET /api/runtime-config` 只返回公开的 `currency`、`timeZone` 和 `defaultPrices`，不暴露其他环境变量，响应禁止缓存。前端必须成功读取配置后才能启动；失败时显示已有的加载失败提示，不猜测币种。

价格优先级不变：配置组价格 → 平台价格 → 内置 LAS 计费项价格 → 部署通用兜底价格。后端计价、价格列表的默认值、从列表新增价格的表单、CSV 模板共用服务端的计费项默认价格；手工新增未知计费项仍使用通用兜底价格。CSV 列名、导入数值和计费单位（例如 token、count、second）不变，金额按部署币种解释，页面标注其单位。

人民币部署可在平台范围一次导入 `prices/platform-default-cny.csv` 的 94 个计费项。导入器同时接受 Core 目录、自定义模型目录和 studio-login 内置价目表中的项目，因此 `operator_unit` 等 Core 目录外的内置计费键也能导入。五个 Seed 语言模型各占一行，使用 `TOKEN_TIER` 结构化规则，按 `BillingContext` 的输入、输出、音频、缓存 token 和输入长度档位计费；客户价与内部成本可分别编辑和导入。缓存存储费、其他推理服务档位和精调价格不在这些公式中。Core 的配套改动为 Seed 2.0 Mini 预估上下文补齐音频 token，并为 Lite/Mini 明确上报音频缓存 token；两端应一起更新，避免预冻结金额偏低。Seedream 5.0 Pro 的 `0.30` 元/张只对应默认 1.5K 单图生成，其他分辨率、图层拆分和额外输入图需要另行计价。配置组已有价格仍优先于平台价格。

USD 部署对应 `prices/platform-default-usd.csv`，同样覆盖 94 个计费项；54 项使用提供的 USD LAS `PriceInfo`，另有 3 项 Seedream 使用 BytePlus 图片刊例价、4 项 Seed 使用 BytePlus Token 档位规则。缺少 USD 报价的项目保留 `0/0`。内置默认值按部署币种选择；已配置的平台与配置组价格继续按原优先级生效，如需替换旧平台价格，导入相应币种的 CSV。

任务创建时继续保存单价快照；回调使用快照和任务原账期。金额保留原有 6 位小数计算结果，单价保留原有 10 位小数，界面总金额仍显示两位小数。后续修改价格不会重新计价已有任务。

## 时间链路

服务端启动时确定部署时区。额度账期、前端默认账期、时间展示、模型统计默认日期与服务端日期筛选使用同一时区。

模型统计采用所选首日当地零点到末日下一天当地零点的半开区间。使用 `@date-fns/tz` 处理时区和夏令时，一天可能为 23 或 25 小时；90 天限制按自然日计算。前端初始化最近七天时也按日历日期计算。

数据库存储表示与业务时区分离：保留项目已有 mysql2 `+08:00` DATETIME 编解码约定，在每个新建连接上固定 session `time_zone = '+08:00'`，让数据库默认时间和 Date 参数一致。SQL 中的到期判断、完成时间、补偿时间统一使用该会话下的 `CURRENT_TIMESTAMP`，不再混用 UTC 或手动加 8 小时。部署时区变化不会改变存储编码；没有调整字段或回写历史数据。

这包含对先前不一致时间表达式的校正：会话和 Ticket 到期按实际有效期判断，补偿任务只在计划时间到达后执行。已有历史记录若曾以其他约定写入，其值不会被本次修改自动校正。

Studio 的 `region`、`tosRegion` 仍由对应 Studio 的部署接口提供，保持原有资源同步逻辑。

## 验证

- `test/deployment.test.ts`：配置校验、公开字段范围、跨月及夏令时边界、无效日期和 90 天范围。
- `test/runtime-config-browser.test.ts`：浏览器配置加载失败时不使用错误币种。
- `test/integration.test.ts` 新增用例：真实 MySQL 的时间往返、登录与 Ticket 过期判断、两币种默认价、价格覆盖和快照、原账期回调、补偿任务到期筛选。Studio 使用 mock。
- 集成测试必须指定独立的 `STUDIO_LOGIN_TEST_DATABASE_URL`，不得使用开发或生产数据库。
